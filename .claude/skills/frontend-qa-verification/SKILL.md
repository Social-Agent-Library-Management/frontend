# Frontend QA Verification

구현 품질과 통합 정합성을 검증하는 절차. **"존재 확인"이 아니라 "교차 비교"**로 런타임에 터질 결함을 미리 잡는다. `npm run build` 통과가 정상 동작을 보장하지 않는다 — 제네릭·캐스팅으로 우회된 불일치는 빌드를 통과하고 런타임에 터진다.

## 검증 우선순위

1. **통합 정합성** — 경계면 불일치가 런타임 에러의 주원인
2. **중복 제거 준수** — 이 하네스의 핵심 가치
3. **스펙 준수** — 레이아웃/토큰/상태/반응형
4. **타입 & 빌드** — tsc/build 통과, any 없음
5. **접근성 & 코드 품질**

## 1. 실제 실행 (읽기만 하지 않는다)

```bash
npx tsc --noEmit      # 타입 에러
npm run build         # 빌드 통과
npm run lint          # 린트
```

빌드가 통과해도 안심하지 않는다. 아래 교차 검증을 별도로 수행한다.

## 2. 통합 정합성 — "양쪽 동시 읽기"

경계면 버그는 양쪽이 각각 "맞아" 보여도 연결에서 어긋난다. 반드시 양쪽을 함께 열어 비교한다.

| 경계면 | 왼쪽(생산자) | 오른쪽(소비자) | 확인 |
|--------|-------------|---------------|------|
| props API | 계획의 인터페이스 | 컴포넌트 파일 props + 호출부 전달 | shape·옵셔널·타입 일치 |
| 데이터 | 스펙의 데이터 shape | 컴포넌트 타입 / 실제 값 | 필드명·null 처리 일치 |
| 라우팅 | `src/app/` page 경로 | `<Link href>`, `router.push`, `redirect` | 링크가 실제 경로를 가리킴 |
| Server/Client | 훅/이벤트 사용 여부 | `"use client"` 유무 | 훅이 서버 컴포넌트에 없음 |

라우팅 검증: `src/app/` 하위 page 파일 경로에서 URL을 추출(라우트 그룹 `(group)`은 URL에서 제거, `[param]`은 동적)하고, 코드의 모든 링크 값과 대조한다.

## 3. 중복 검사 (핵심)

이 하네스의 존재 이유다. 다음을 확인한다:

- **계획의 "재사용" 항목이 실제로 임포트됐는가.** 새로 복제했으면 FIX. 계획서와 실제 임포트를 대조한다.
- **반복 마크업.** 거의 동일한 JSX/className 블록을 grep으로 찾는다. 2회 이상인데 컴포넌트/map으로 안 묶였으면 FIX.
  ```bash
  grep -rn "className=" src/ | sort | uniq -c | sort -rn | head
  ```
- **손이어붙인 조건부 className.** variant를 cva로 안 뺀 경우 지적.
- **과도한 추상화.** 1회용인데 불필요하게 래핑한 컴포넌트도 지적(반대 방향 결함).

## 4. 스펙 준수

`_workspace/01_design-spec.md`와 대조:
- 레이아웃 트리 일치
- 상태 구현: hover/focus/disabled/loading/empty/error
- 반응형 브레이크포인트 동작
- 색/타이포/간격이 `@theme` 토큰 사용 — 하드코딩 hex/px를 grep으로 탐색
  ```bash
  grep -rnE "#[0-9a-fA-F]{3,6}|\[[0-9]+px\]" src/components src/app
  ```

## 5. 접근성 & 코드 품질

- 시맨틱 태그, `aria-*`, 키보드 동작, `alt`, 포커스 링(`focus-visible:ring`)
- 미사용 임포트/변수, 명명 규칙

## 판정 & 리포트

각 항목을 **PASS / FIX / REDO**로.
- FIX/REDO는 반드시 **파일:라인 + 구체적 수정 방법**을 적는다("여기 잘못됨"이 아니라 "무엇을 어떻게").
- 스펙이 "미확정"인 항목은 FIX가 아니라 **"미검증(스펙 미확정)"**으로 분류 → 사용자 확인 대상.

`_workspace/04_qa-report.md`:
```
## 요약 (PASS/FIX/REDO 수, tsc·build·lint 결과)
## 항목별 판정 (항목 | 판정 | 근거 | 수정 지시)
## 통합 정합성 발견
## 중복 발견
## 미검증/보류 항목
```

## 점진 검증 (incremental)

전체 완성 후 1회가 아니라, **각 모듈(프리미티브/합성/페이지) 완성 직후** 검증한다. 초기 경계면 불일치가 후속 모듈로 전파되는 것을 막는다.

## 재검증 루프

FIX/REDO를 담당 에이전트에게 전달하고 수정 후 재검증한다. **최대 2회.** 이후에도 남으면 경고와 함께 사용자 판단을 요청한다(무한 루프 방지).

## 원칙 요약
- **실행한다.** tsc/build/lint/grep을 직접 돌린다.
- **양쪽을 동시에 읽는다.** 경계면은 한쪽만 보면 못 잡는다.
- **중복을 집요하게 찾는다.** 계획 대비 실제 임포트, grep으로 반복 마크업.
- **수정 지시는 구체적으로.** 파일:라인 + 방법.
